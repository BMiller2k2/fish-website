# 🐟 Fish Finder

A small website for browsing a catalog of fish and asking an LLM-powered
chatbot questions about them. The chatbot is grounded in your fish catalog and
answered by Google's Gemini.

**Stack:** ASP.NET Core (C#) minimal-API backend + Angular single-page frontend,
one deployable — the built Angular app is served from the API's `wwwroot`.
Data is stored in SQLite via EF Core.

## What's inside

| Path | Purpose |
| --- | --- |
| `Program.cs` | Host setup: .env loading, EF Core, static SPA hosting, endpoint wiring |
| `Api/` | Minimal-API endpoint groups — `FishEndpoints`, `AdminEndpoints`, `ChatEndpoints` |
| `Persistence/` | `AppDbContext`, the `fish.json` seeder, the slug helper |
| `Models/` | `Fish` / `FishFact` entities and the API DTOs |
| `Services/` | `GeminiChatService` (chat proxy), `AdminAuth`, the `.env` loader |
| `ClientApp/` | Angular app (standalone components, signals, router) |
| `wwwroot/` | Angular build output — generated by `ng build`, git-ignored |
| `data/fishfinder.db` | The catalog — a SQLite database, created on first run, git-ignored |
| `data/fish.json` | Seed data. Read once, to populate an empty database. |
| `legacy/` | The original Node.js/Express version, kept for reference — still runnable on its own |

## Prerequisites

- **.NET SDK 10** — <https://dotnet.microsoft.com/download>
- **Node.js 20+** — for building the Angular app
- A **Gemini API key** — <https://aistudio.google.com/apikey>

## Setup

```bash
cp .env.example .env      # then edit .env and paste your GEMINI_API_KEY

# from the repo root
dotnet run
```

The first `dotnet run` (or `dotnet build`) builds the Angular app into `wwwroot`
automatically if it isn't there yet, then serves everything on
<http://localhost:5152>.

### Day-to-day development (live reload)

Run the two dev servers side by side:

```bash
# terminal 1 — the API, watching C# files
dotnet watch

# terminal 2 — the Angular dev server (proxies /api to :5152)
cd ClientApp
npm start
```

Then open <http://localhost:4200>. Angular's dev server proxies `/api/*` to the
C# server (see `ClientApp/proxy.conf.json`), so there's no CORS setup.

### Production build

```bash
dotnet publish -c Release -o out
# `dotnet publish` runs `ng build` and bundles wwwroot into the output
cd out && dotnet FishFinder.dll
```

## The database

The catalog lives in a SQLite file at `data/fishfinder.db` (override with `DB_FILE`),
using two tables:

| Table | Columns |
| --- | --- |
| `fish` | `Id`, `Name`, `ScientificName`, `Habitat`, `Diet`, `Size`, `ImageUrl`, `Description`, `CreatedAt`, `UpdatedAt` |
| `fish_facts` | `FishId` → `fish(Id)` (`ON DELETE CASCADE`), `Position`, `Fact` — one row per "did you know?" fact |

`AppDbContext` creates the schema on startup (`EnsureCreated`). On the **first
run against an empty database**, `FishSeeder` imports every fish from
`data/fish.json`. After that the JSON file is ignored — manage fish through the
admin page or the API. To re-seed, delete `data/fishfinder.db` and restart.

## API

All JSON, all under `/api`.

| Method | Route | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/fish` | — | list all fish |
| `POST` | `/api/fish` | admin | add a fish |
| `PUT` | `/api/fish/{id}` | admin | update (send only the fields you're changing) |
| `DELETE` | `/api/fish/{id}` | admin | remove a fish |
| `GET` | `/api/admin/config` | — | `{ tokenRequired }` |
| `POST` | `/api/admin/login` | — | validate a token |
| `POST` | `/api/chat` | — | catalog-grounded Gemini proxy |

## Authentication

A single shared token, no user accounts. Set `ADMIN_TOKEN` in the environment;
writes then require a matching `X-Admin-Token` header. `/login` (an Angular
route, not linked from the public site) checks the token via
`POST /api/admin/login` and stores it in the browser's `localStorage`; the
route guard on `/admin` redirects there when a token is required but missing.
With no `ADMIN_TOKEN` set, the admin API is open (local dev).

## How the chatbot works

`POST /api/chat` takes the conversation history from the browser, loads the full
fish catalog from the database, injects it into the Gemini system instruction as
context, and calls the `generateContent` REST API with `HttpClient`. The API key
stays on the server. Model defaults to `gemini-3.6-flash` (override with
`GEMINI_MODEL`).

## Configuration

| Variable | Default | Effect |
| --- | --- | --- |
| `GEMINI_API_KEY` | — | required for the chatbot |
| `GEMINI_MODEL` | `gemini-3.6-flash` | which Gemini model to call |
| `ADMIN_TOKEN` | _(unset)_ | if set, writes require the token and `/admin` needs sign-in |
| `DB_FILE` | `data/fishfinder.db` | SQLite file location |
| `ASPNETCORE_URLS` | `http://localhost:5152` | listen address |

Read from `.env` at the repo root (real environment variables win) or set
directly in the environment.

## Deploying

- Set `GEMINI_API_KEY` and a strong `ADMIN_TOKEN` as environment variables.
- `data/fishfinder.db` is a file on disk — use a host with a persistent filesystem, or
  point `DB_FILE` at a mounted volume, or switch `AppDbContext` to a networked
  database (`UseNpgsql` / `UseSqlServer`).
- The published output is a normal ASP.NET Core app: `dotnet FishFinder.dll`.
